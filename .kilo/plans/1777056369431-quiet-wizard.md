# SQL Schema Fix & Enterprise Extension Plan

## Problem Summary

The current Supabase schema has critical inconsistencies and is missing core tables for an enterprise ticketing system.

**Immediate issues found:**
1. `events` table has **duplicate FK** to `organizations` (`org_id` AND `organization_id`) — `org_id` is never used in code
2. `profiles` table exists but is **completely ignored** by the app (uses `user_metadata` instead)
3. `organizations` table is minimal — no partner fields (city, type, description, socials)
4. `events` table missing columns that the app already uses (`description`, `total_tickets`, `sold_tickets`)
5. No `orders`, `tickets`, `event_pricing_tiers`, or payment tables exist
6. Text types with CHECK constraints instead of Postgres enums — less type-safe
7. No `updated_at` triggers on any table
8. RLS policies check `organization_id` but table also has `org_id` (data integrity risk)

## Phase 2: Fix & Extend `profiles`

**Current schema:**
```
id, email, role (user_role), full_name, created_at
```

**Extended schema:**
```sql
CREATE TABLE public.profiles (
  id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  email text NOT NULL,
  full_name text,
  phone text,
  avatar_url text,
  bio text,
  date_of_birth date,
  city text,
  locale text NOT NULL DEFAULT 'pl',
  email_verified boolean NOT NULL DEFAULT false,
  phone_verified boolean NOT NULL DEFAULT false,
  role user_role NOT NULL DEFAULT 'user',
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT profiles_pkey PRIMARY KEY (id)
);

-- Sync profile on user creation
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.profiles (id, email, full_name)
  VALUES (
    NEW.id,
    NEW.email,
    COALESCE(NEW.raw_user_meta_data->>'full_name', '')
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

**Key changes:**
- Add phone, avatar_url, bio, date_of_birth, city, locale
- Add email_verified, phone_verified flags
- Add updated_at with auto-update trigger
- Add `ON DELETE CASCADE` on FK to auth.users
- Add trigger to auto-create profile on auth.users insert
- Drop `role` default that references undefined type, re-create with proper enum

## Phase 3: Fix & Extend `organizations` ( = Partners )

**Current schema:**
```
id, name, slug (unique), logo_url, created_at, invite_code (unique)
```

**Extended schema:**
```sql
CREATE TABLE public.organizations (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  name text NOT NULL,
  slug text NOT NULL UNIQUE,
  logo_url text,
  description text,
  website_url text,
  city text,
  address text,
  type org_type NOT NULL DEFAULT 'club',
  status org_status NOT NULL DEFAULT 'active',
  is_verified boolean NOT NULL DEFAULT false,
  contact_email text,
  contact_phone text,
  social_instagram text,
  social_facebook text,
  social_soundcloud text,
  tpay_merchant_id text,
  tpay_security_code text,  -- encrypted at app level, for CRC verification
  invite_code text UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT organizations_pkey PRIMARY KEY (id)
);
```

**Key changes:**
- Add partner fields: description, website_url, city, address
- Add `type` enum (club, collective, festival_organizer, promoter, venue, other) — replaces hardcoded `Partner.type`
- Add `status` and `is_verified` for moderation flow
- Add contact fields: contact_email, contact_phone
- Add social links: instagram, facebook, soundcloud
- Add TPay merchant fields for per-org payouts
- Add updated_at trigger
- This table replaces the hardcoded `src/lib/partners.ts` data

## Phase 5: Fix `events`

**Current issues:** duplicate FK (`org_id` + `organization_id`), missing columns app uses.

```sql
CREATE TABLE public.events (
  id uuid NOT NULL DEFAULT gen_random_uuid(),
  organization_id uuid NOT NULL REFERENCES public.organizations(id) ON DELETE CASCADE,
  title text NOT NULL,
  subtitle text,
  slug text UNIQUE,
  description text,
  date timestamptz NOT NULL,
  end_date timestamptz,
  venue_name text NOT NULL,
  venue_city text,
  price numeric NOT NULL DEFAULT 0.00,
  currency text NOT NULL DEFAULT 'PLN',
  min_age int NOT NULL DEFAULT 18,
  genre event_genre,
  type event_type,
  status event_status NOT NULL DEFAULT 'draft',
  promo_tier promo_tier NOT NULL DEFAULT 'none',
  image_url text,
  total_tickets int NOT NULL DEFAULT 0,
  sold_tickets int NOT NULL DEFAULT 0,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT events_pkey PRIMARY KEY (id)
);

-- Index for common queries
CREATE INDEX idx_events_organization_id ON public.events(organization_id);
CREATE INDEX idx_events_date ON public.events(date);
CREATE INDEX idx_events_status ON public.events(status);
CREATE INDEX idx_events_slug ON public.events(slug);
```

**Key changes:**
- **DROP `org_id` column entirely** — only `organization_id` is used in code
- Add `slug` for SEO-friendly URLs
- Add `description` (app already queries this)
- Add `end_date` for multi-day events/festivals
- Rename `venue` → `venue_name`, add `venue_city`
- Add `currency` (default PLN)
- Add `min_age` (default 18)
- Add `total_tickets`, `sold_tickets` (app already queries these)
- Replace all text/CHECK with proper enums
- Add `updated_at` trigger
- Add indexes for common query patterns

## Phase 7: Utility Functions & Triggers

```sql
-- Auto-update updated_at on any row change
CREATE OR REPLACE FUNCTION public.update_updated_at()
RETURNS trigger AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Apply to all tables with updated_at
CREATE TRIGGER set_profiles_updated_at
  BEFORE UPDATE ON public.profiles
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();

CREATE TRIGGER set_organizations_updated_at
  BEFORE UPDATE ON public.organizations
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();

CREATE TRIGGER set_events_updated_at
  BEFORE UPDATE ON public.events
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();

CREATE TRIGGER set_orders_updated_at
  BEFORE UPDATE ON public.orders
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();

CREATE TRIGGER set_refunds_updated_at
  BEFORE UPDATE ON public.refunds
  FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();
```

## Phase 8: RLS Policies

### `profiles`
```sql
ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Profiles are readable by everyone" ON public.profiles FOR SELECT USING (true);
CREATE POLICY "Users can update own profile" ON public.profiles FOR UPDATE USING (auth.uid() = id);
```

### `organizations`
```sql
ALTER TABLE public.organizations ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Organizations are readable by everyone" ON public.organizations FOR SELECT USING (true);
CREATE POLICY "Authenticated users can create organizations" ON public.organizations FOR INSERT WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "Owners and admins can update their organizations" ON public.organizations FOR UPDATE USING (is_org_admin(id));
```

### `organization_members`
```sql
ALTER TABLE public.organization_members ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can read their own memberships" ON public.organization_members FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Members can see co-members" ON public.organization_members FOR SELECT USING (organization_id IN (SELECT get_my_organizations()));
CREATE POLICY "Owners and admins can manage members" ON public.organization_members FOR ALL USING (is_org_admin(organization_id));
```

### `events`
```sql
ALTER TABLE public.events ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Events are readable by everyone" ON public.events FOR SELECT USING (true);
CREATE POLICY "Org members can insert events" ON public.events FOR INSERT WITH CHECK (organization_id IN (SELECT get_my_organizations()));
CREATE POLICY "Org members can update events" ON public.events FOR UPDATE USING (organization_id IN (SELECT get_my_organizations()));
CREATE POLICY "Org members can delete events" ON public.events FOR DELETE USING (organization_id IN (SELECT get_my_organizations()));
```

### `orders` — users see own orders, org members see orders for their events
```sql
ALTER TABLE public.orders ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own orders" ON public.orders FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Org admins can view orders for their events" ON public.orders FOR SELECT USING (event_id IN (SELECT e.id FROM public.events e WHERE e.organization_id IN (SELECT get_my_organizations())));
CREATE POLICY "Users can create orders" ON public.orders FOR INSERT WITH CHECK (auth.uid() = user_id);
```

### `tickets` — users see own tickets, org members can scan
```sql
ALTER TABLE public.tickets ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can view own tickets" ON public.tickets FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "Org admins can view tickets for their events" ON public.tickets FOR SELECT USING (event_id IN (SELECT e.id FROM public.events e WHERE e.organization_id IN (SELECT get_my_organizations())));
```

### `ticket_scans` — org members only
```sql
ALTER TABLE public.ticket_scans ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Org members can manage scans" ON public.ticket_scans FOR ALL USING (event_id IN (SELECT e.id FROM public.events e WHERE e.organization_id IN (SELECT get_my_organizations())));
```

## Migration Strategy

Since there's no existing migration system, we need to:

1. **Create `supabase/` directory** in project root with migration files
2. **Install Supabase CLI** locally (`npx supabase init`)
3. **Write migration files** in order:
   - `001_create_enums.sql`
   - `002_fix_events_table.sql` (drop `org_id`, add missing columns, change types)
   - `003_extend_profiles.sql`
   - `004_extend_organizations.sql`
   - `005_fix_organization_members.sql`
   - `006_create_event_pricing_tiers.sql`
   - `007_create_orders.sql`
   - `008_create_tickets.sql`
   - `009_create_ticket_scans.sql`
   - `010_create_refunds.sql`
   - `011_create_triggers.sql`
   - `012_create_rls_policies.sql`

4. **Data migration**: Insert existing hardcoded partners into `organizations` table
5. **Backfill**: Migrate `user_metadata.full_name` → `profiles.full_name` for existing users
