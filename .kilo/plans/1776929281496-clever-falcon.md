- Export a helper function `createSupabaseServerClient(Astro)` that:
  - Reads `PUBLIC_SUPABASE_URL` and `PUBLIC_SUPABASE_ANON_KEY`
  - Creates a server client with cookie-based auth
  - Returns the client
- Add env var validation (throw if missing)

**Modify:** `src/lib/supabase.ts` — keep existing client-side client unchanged (used by Svelte components for interactive features like OAuth redirects)

---

## Phase 4: Create Astro middleware for SSR auth

**New file:** `src/middleware.ts`

The middleware will:
1. Create a server-side Supabase client per request using cookies
2. Call `supabase.auth.getUser()` to get the current user (validates JWT from cookie)
3. Store `{ user, session, supabaseServer }` in `Astro.locals`
4. For `/panel/*` routes: if no user → redirect `302` to `/?login=1`
5. Pass through for all other routes

This eliminates the client-side redirect flash in `DashboardLayout.svelte`.

---

## Phase 5: Create API routes for auth actions

**New file:** `src/pages/api/auth/login.ts`
- POST endpoint: accepts `{ email, password }`
- Uses server-side Supabase client
- Calls `supabase.auth.signInWithPassword()`
- Sets session cookies via Supabase SSR
- Returns `{ success: true }` or `{ error: string }`

**New file:** `src/pages/api/auth/register.ts`
- POST endpoint: accepts `{ email, password, fullName }`
- Calls `supabase.auth.signUp()`
- Returns result

**New file:** `src/pages/api/auth/logout.ts`
- POST endpoint
- Calls `supabase.auth.signOut()`
- Clears cookies
- Returns `{ success: true }`

**New file:** `src/pages/api/auth/callback.ts`
- GET endpoint for OAuth redirects (Google/Apple)
- Exchanges code for session using `supabase.auth.exchangeCodeForSession()`
- Redirects to `/panel/bilety`
